## 1 什么是基数排序

基数排序是一种非比较型的整数排序算法，于快速排序和归并排序两两比较来排序的算法不同，基数排序是通过将数字按位数（个位、十位、百位等）切割，然后对每个位数分别进行“分配”和“收集”来实现排序的。

### 1.1 核心思想

基数排序的核心在于“分桶” 。对于十进制数，我们有 0 到 9 这 10
个数字，因此我们需要 10
个“桶”。算法会根据数字在某一位上的值，将它们放入对应的桶中，然后再按顺序从桶中收集起来。

基数排序主要分为两种主要方式：

- **LSD (Least Significant Digit -
  最低位优先)**：从数字的最右边（个位）开始，逐步向左（十位、百位）进行排序。这在整数排序中最常用。
- **MSD (Most Significant Digit -
  最高位优先)**：从数字的最左边（最高位）开始，逐步向右进行排序。通常用于字符串排序或非常长的整数。

### 1.2 样例示范

假设我们有一个无序数组：`[170, 45, 75, 90, 802, 24, 2, 66]`

**第一步：确定最高位数** 找出数组中的最大值，确定需要进行几轮排序。   
      

找出数组中的最大值，确定需要进行几轮排序。最大值是 `802`，它有 3
位数（百位）。因此，我们需要进行 3 轮排序（个位、十位、百位）。

第二步：按个位数排序（第一轮）

将数字根据**个位数**放入 0-9 的桶中：

桶 0：17**0**, 9**0**

桶 1：(空)

桶 2：80**2**, **2**

桶 3：(空)

桶 4：2**4**

桶 5：4**5**, 7**5**

桶 6：6**6**

收集桶中的数字（保持放入的先后顺序，这就是基数排序是**稳定排序**的原因）：
当前数组变成：`[170, 90, 802, 2, 24, 45, 75, 66]`

第三步：按十位数排序（第二轮）

将上一步的结果，根据**十位数**放入桶中（注意，数字 `2` 的十位可以看作
`0`）：

桶 0：8**0**2, 0**0**2 (即2)

桶 1：(空)

桶 2：**2**4

桶 3：(空)

桶 4：**4**5

桶 5：(空)

桶 6：**6**6

桶 7：1**7**0, **7**5

桶 8：(空)

桶 9：**9**0

收集数字，当前数组变成：`[802, 2, 24, 45, 66, 170, 75, 90]`

**第四步：按百位数排序（第三轮）**
将上一步的结果，根据**百位数**放入桶中（位数不够的补0，如 `24` 视作
`024`）：

桶 0：00**2**, 0**2**4, 0**4**5, 0**6**6, 0**7**5, 0**9**0

...

桶 8：**8**02

最终收集数字，数组变为完全有序： `[2, 24, 45, 66, 75, 90, 170, 802]`

### 1.3 为什么LSD（最低位优先必须从最低位开始）

其实就是为了让高位的排序权重覆盖低位的排序权重。

**核心原理：**
当我们在处理更高的位（比如十位）时，如果两个数字的十位不同，它们会被分到不同的桶里，高位的大小直接决定了先后顺序。**如果两个数字的高位相同（比如
`12` 和
`15`），由于它们进入同一个桶，并且基数排序是“稳定排序”，它们在桶里的先后顺序依然保持着上一轮（个位数）排好的顺序。**
因此，LSD 必须把最重要的判定（最高位）留到最后一步来做。

### 1.4 MSD算法思想的介绍

MSD 的核心思想是**分治法 (Divide and Conquer)** 和**递归 (Recursion)**。

#### MSD 的详细执行步骤：

假设我们有数组：`[170, 045, 075, 090, 802, 024, 002, 066]`
（为了方便，不足 3 位的在前面补 0）

**第一步：按最高位（百位）分桶**

桶 0：`[045, 075, 090, 024, 002, 066]`

桶 1：`[170]`

...

桶 8：`[802]`

**第二步：关键分化（局部递归）** MSD
**不会**在这一步把桶里的数字收集成一个大数组。相反，它会检查每个桶：

对于桶 1 (`[170]`) 和 桶 8
(`[802]`)：里面只有一个元素，说明它们已经完全排好序了，不需要再处理。

对于桶 0：里面有多个元素，说明这些数字的百位都是
0，分不出胜负。**我们需要单独对桶 0
里的这组数据，进行“下一位（十位）”的排序。**

**第三步：对子桶继续细分（处理桶 0 的十位）** 将
`[045, 075, 090, 024, 002, 066]` 按**十位**再次分入子桶：

子桶 0：`[002]` (完成)

子桶 2：`[024]` (完成)

子桶 4：`[045]` (完成)

子桶 6：`[066]` (完成)

子桶 7：`[075]` (完成)

子桶 9：`[090]` (完成)

如果某个子桶里还有多个元素，就继续看个位，以此类推。

**第四步：按顺序合并所有桶**

当所有的桶和子桶都只剩 0 个或 1
个元素，或者所有位数都比较完毕后，将所有桶按顺序拼接起来，就得到了最终有序的数组。

### 1.6 关于LSD和MSD的选择

|  |  |  |
|----|----|----|
| 维度 | LSD (最低位优先) | MSD (最高位优先) |
| 处理方式 | 整体分桶 -> 整体收集 -> 循环下一位 | 整体分桶 -> 局部独立分桶 -> 递归到最低位 |
| 适用场景 | 适合**位数固定**、长度差不多的数字（如普通整数）。 | 适合**位数差异大**的数据，尤其是**字符串排序**（比如英文单词字典序）。 |
| 优势 | 实现简单，没有递归调用的开销，代码通常是迭代的。 | 可以“提前结束”。比如排两个很长的单词 `apple` 和 `banana`，看第一个字母就分出胜负了，不需要比较后面的字母。 |
| 劣势 | 哪怕最高位已经排好了，也必须死板地排完所有的低位。 | 会产生大量的子桶，空间开销较大；递归较深时容易影响性能。 |

### 2.2 切片与分期：LSD（最低位优先）的魔法

面对 32 位的庞大整数，机器无法一次性看全全局。我们的策略是切碎它！将 32
位整数切 成 4 份，每份 1 个字节（范围 0-255）。

为什么必须从低位往高位排（LSD, Least Signiffcant
Digit）？我们可以用一个生活中的例子 来理解：

举例：给全校学生按“出生年月日”排序。
如果我们先按“年份”排（最高位），再按“月份”排，你会发现，按月份重新排队
时，原本已经排好的“年份”顺序全乱套了！

正确的做法是：

- 第一轮（低位打底）：先不管年月，把所有人按“日”排好队。
- 第二轮（保住战果）：在“日”的基础上，按“月”重新排队。此时同月出生的
  人，天然保留了按“日”递增的顺序。
- 第三轮（一锤定音）：按“年”排队。年份最大的人直接去最后面；年份相同的
  人，完全依靠前两轮排出的顺序决定先后！

每一轮的高位，都赋予了低位“稳定性”的意义。这就是连续跑 4
轮字节排序的底层逻辑。

### 2.4 如何处理负数

在计算机中，负数的最高位（符号位）是 1，正数是
0。如果直接当成无符号数去排，负数会因为最高位大而被排到正数的后面。

破局点：符号位反转。排序前，将所有数字异或
0x80000000（翻转最高位）。负数变成 0 跑 到前面，正数变成 1 去了后面。4
轮排序结束后，再次异或脱掉“马甲”，就能得到完美的真实 顺序。
